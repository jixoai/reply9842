## 14. 跨 server 与回归的真实验证（2026-11-24，上线前实证）

环境：
- 第一台 relay：香港 118.26.39.57（生产）
- 第二台 relay：上海 47.117.152.3（阿里云，本次临时部署，验证后已停止并关闭端口）
- 可控上游：本机流式 echo（避免 401 短路导致服务端不落基线）

### A6 跨 server 切换可恢复（**通过**）

10 次相同 400KB 流式请求，线路 A/B 指向**两台不同 relay**：

| 请求 | 线路 | 编码 | 含义 |
|---|---|---|---|
| 1 | A | `zstd` | 首次无基线 |
| 2 | **B** | **`resend-full`** | 跨 server：B 无 A 的基线 → miss → 自动全量重发 |
| 3 | A | `zstd` | Forget 生效（旧基线已丢），重建 |
| 4-10 | A | **`dcz2` 命中** | 稳定（92B 传 400KB） |

**10/10 全部 200，数据完整** → 「跨 server 切换是可恢复的降级，不是数据损坏」成立。

### A5 同 server 多线路 delta 无损（**通过**）

两条线路指向**同一台** relay，10 次请求：**delta 命中 9 次（90%）**，
编码分布 `zstd×1 + dcz2×9`。

### A9 单线路零退化（**通过，有对照基线**）

同一测试分别跑旧版（f6977b3^）与新版：

| 版本 | delta 命中 | 编码分布 | 上行 wire |
|---|---|---|---|
| 旧版 | 9/10 (90%) | zstd×1, dcz2×9 | `[112, 92, 92, …]` |
| 新版 | 9/10 (90%) | zstd×1, dcz2×9 | 完全相同 |

→ 「transport/enc 分布不退化」有了可对照的实证，不再只是「配置等价」。

### 验证中修复的真实缺陷

- [x] 14.1 **单 server delta 振荡**：初版的 `Finder.Forget` 无条件丢弃 miss 的基线，
      导致单 server 也陷入「zstd → resend-full → zstd → …」永久振荡（实测复现）。
      改为**只在配置含多条指向不同 server 的线路时才丢**（`handler.multiServer()`）
- [x] 14.2 新增 `Finder.Forget` 及其两个测试（删指定基线 / 不误删其它）
