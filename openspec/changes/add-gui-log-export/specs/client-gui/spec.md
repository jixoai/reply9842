## ADDED Requirements

### Requirement: 运行日志必须可从界面取出

GUI SHALL 提供运行日志的可见出口：在设置页展示最近 N 行运行日志（只读、等宽、可滚动），
并提供一键复制。这不仅是便利功能——Windows 上 GUI 是 `windowsgui` 子系统、没有终端，
界面是该日志的唯一可见通道。

实现约束：不新增依赖（用既有 `mygo.Clipboard`）；日志行数上限保持有界（当前 200 行）。

#### Scenario: 出错时能拿到日志

- **WHEN** 转发因错误配置失败（例如错误的 `-server`）
- **THEN** 设置页的诊断小节能看到对应的错误行，且「复制全部」可把完整日志放进剪贴板

#### Scenario: 无日志时不显示空卡片

- **WHEN** 应用刚启动、还没有任何日志
- **THEN** 诊断小节显示「暂无日志」文案，不是一张空白卡片

#### Scenario: 超长错误行不撑破布局

- **WHEN** 某条日志包含很长的错误文本
- **THEN** 该行在卡片内被裁剪为单行省略，卡片宽度不变

### Requirement: 统计器失败原因必须可见

GUI SHALL 在界面上展示统计器打开失败的原因（`Runner.StatsErr()`），而不是只写进代码
注释与日志。统计起不来不该拖住转发，但也不能静默。

#### Scenario: 统计文件不可写时用户看得到

- **WHEN** `-stats` 指向一个不可写路径
- **THEN** 界面显示「统计不可用 + 原因」，转发仍正常运行
