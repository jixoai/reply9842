## ADDED Requirements

### Requirement: 服务端是单实例亲和，不得声称可水平扩展

服务的状态语义 SHALL 被准确表述与遵守：**协商状态为零**（无目录、无版本号、无会话 ID，
协商开销恒为 32 字节哈希），但**缓存状态有**（字典 LRU 在内存、幂等区在磁盘 spool）。
因此部署形态是单实例亲和，多副本会让压缩收益按比例归零且续传必然 miss。

文档不得出现「服务端完全无状态，可水平扩展」这类与实现矛盾的表述。

#### Scenario: 落到别的实例时退化为无字典压缩

- **WHEN** 请求被负载均衡到与上次不同的实例
- **THEN** 该实例 store 里没有对应 `BaseHash`，返回 `FrameDeltaMiss`，客户端重发全量
      （功能正确，压缩收益归零）

#### Scenario: 跨实例续传必然 miss

- **WHEN** 客户端重连到与原请求不同的实例
- **THEN** 幂等区查不到该 key，按 ResumeMiss 处理

#### Scenario: 文档表述与实现一致

- **WHEN** 阅读 README / 官网 / DEPLOY
- **THEN** 它们说明「无会话协商状态、有缓存状态、单实例亲和」，不声称可水平扩展
