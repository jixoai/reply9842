# Tasks: fix-stateless-claim-vs-implementation

## 1. 文档改口（核心）

- [ ] 1.1 `README.md` 第 3 条设计决策改写：区分「与会话无关的协商状态」与「缓存状态」。
      建议措辞要点：
      - **无目录、无版本号、无会话 ID、无需双向协商** → 这些仍然成立，是与 SDCH 的本质
        区别，也是 32 字节恒定协商成本的来源
      - **但服务端有缓存状态**：字典 LRU（内存，`-cache-mb`）+ 幂等 spool（磁盘，
        `-spool-dir`）；因此**不做水平扩展**，反代/负载均衡必须保证单客户端粘性
- [ ] 1.2 `README.md` 已知限制新增一条「单实例亲和」，说明滚动重启的代价
- [ ] 1.3 `site/index.html:361` 附近同样的「服务端完全无状态」表述同步改写
      （官网与 README 不能一个说法一个做法）
- [ ] 1.4 `DEPLOY.md` 新增「运维注意」小节：重启会清空 `tmp/`、会让压缩率短暂归零、
      会让未完成的续传失效；建议在低峰重启
